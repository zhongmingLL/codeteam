## 1. bwrap / user namespace (AC-13, D3)

Commands and results:

```text
unshare -Ur true      -> exit 0
unshare -Ur -m true   -> exit 0
unshare -Ur -n true   -> exit 0
```

Sandbox probe:

```bash
bwrap --unshare-all --die-with-parent --ro-bind / / --tmpfs /home --tmpfs /tmp \
  --dev /dev --proc /proc sh -c 'id; ls -A /home | wc -l; ls /proc | grep -c "^[0-9]"; ...'
```

Observed:

- `/home` has 0 entries (host home is not mounted);
- PID namespace shows 5 processes, not the host process tree;
- network namespace has 1 interface (`lo` only);
- `/tmp` is writable inside the sandbox; `/etc/hostname` write fails with `Read-only file system`;
- capabilities inside the sandbox: `CapPrm=0`, `CapEff=0`.

Conclusion: unprivileged user namespaces and bwrap isolation (mount/PID/net) are **available on this
WSL2 host**. D3 is not reopened.

Host dependency recorded for W2: a target Linux runner must re-run the same probe. If it lacks
unprivileged userns/bwrap, D3 reopens with this fallback: no command execution without an
operator-visible approval step, or run the worker in a dedicated VM/container runner; the sandbox
claim must not silently degrade.

## 2. Low-privilege user × worktree (AC-14)

`sudo` is unavailable, so a second OS user could not be created. Instead the permission model was
enforced with real mount namespaces and a read-only bind, which is the mechanism the sandbox will
use:

| Role | Mount | Result |
|---|---|---|
| worker | `--bind <worktree> <worktree>` | `task.txt` append succeeds; evidence write succeeds |
| reviewer | `--ro-bind <worktree> <worktree>` + rw evidence | reading works; append fails with `Read-only file system`; evidence write succeeds |
| reviewer (escape attempt) | same sandbox | `mount -o remount,rw` fails: `must be superuser`; `CapEff=0` |

Modes used: directories `750`, file `640`. No `chmod 777` anywhere.

Limitation: the probe runs as the same kernel uid, so enforcement comes from sandbox confinement
plus the read-only mount, not from a distinct uid. Production reviewer/verifier isolation should
still use separate OS users; that validation needs a host with `sudo` (CI runner) and is a W2 entry
check. The design does not depend on world-writable paths.
