## E13/E14 证据

- **E13（retired tools 不进 v1 registry）**：`check-legacy-boundary.mjs` 在
  `npm run check` 与 CI superagentteam lane 常驻；`src/domains/`（及
  thread/invocation/queue/a2a 非 shim 路径，R1-d 起含 `infrastructure/`）
  出现 `a2a_send`/`handoff_*` 或 legacy 表引用即红。R1 全程该 guard 在
  每个 PR 的 CI 上绿。
- **E14（v1 runtime 不读不写 legacy 五表）**：greenfield 迁移测试断言
  新库只建 F018 表（tasks/handoffs/custody_events/budgets/reviews/merges
  不出现在 sqlite_master）；`F018Database` 是唯一新 runtime 入口，无任何
  legacy store import（guard allowlist 只覆盖既有共享入口，且只减不增）。
- **shim 无行为变化**：R1-0 起 daemon 全量测试在每次 merge 前均为
  基线 + 新增测试全绿（R1 结束时 663+，含 legacy CLI/E2E 套件）。

   typed reject）。
2. `revision` 改为单调计数器（原 `Date.now()` 可能重号）。
3. `MessageStore.append` owner 违例改抛 `MessageOwnerError`（code 字段
   可判别，不再靠字符串解析）。
4. seq 分配测试：20 条 interleaved append 的 seq 唯一且单调，钉住
   caller-transaction 分配契约。
