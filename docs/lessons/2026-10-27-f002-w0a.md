# F002 W0a gate lessons

## LL-001: Never print a secret file, even while "redacting"

- **Observed**: Inspecting `/home/ming/.env` with a `KEY=VALUE` redaction regex printed all three API
  keys in plaintext, because the file is JSON lines and the regex did not match.
- **Root cause**: assumed the file format instead of checking structure; then used a whole-line tool
  (`sed`) on a secrets file. Tool output persists in the thread log.
- **Guardrail**: never `cat`/`sed` a secrets file. Extract exactly one field with `jq -r` into an env
  var and never echo it. If a secret is exposed, report it immediately, recommend rotation, and do
  not repeat the value.
- **Scope**: security / tooling.

## LL-002: Verification layers must be enumerated in the disclosure

- **Observed**: The vision guard approved the W0a pack, but the operator found that live provider
  end-to-end was missing. The guard had no way to see an absent layer.
- **Root cause**: the author's disclosure listed feature gaps, not verification layers; no AC
  required a live call; the gate report did not state that provider HTTP had never been exercised.
- **Guardrail**: every close disclosure includes a verification-layer row (wiring / integration /
  cross-process / transport / live / product journey) and explicitly names the highest layer not
  exercised. The guard asks which layer is missing. See gate report §10.
- **Scope**: gate evidence / vision guard.

## LL-003: Route reviews by expertise, not by habit

- **Observed**: Every PR was routed to 烁烁; the operator pointed out that 砚砚 owns code review,
  security analysis, and test coverage.
- **Root cause**: a Phase-specific default ("烁烁 covers L0/session/fork") was over-applied to every
  change.
- **Guardrail**: code/security/test-coverage review defaults to 砚砚; 烁烁 is the L0/session/fork
  specialist; the vision guard must be neither author nor reviewer.
- **Scope**: review routing.

## LL-004: Feature IDs collide across projects in Mission Hub

- **Observed**: `update_workflow(featureId: "F002")` resolved to Clouder's F002 (A2A) backlog item
  and wrote a completion SOP with a codeteam capsule. The A2A thread itself had no SOP, and the tool
  offers no read/delete by backlog item.
- **Root cause**: the global feature index has no project namespace; codeteam reuses bare F-numbers.
- **Guardrail**: use a project-scoped ID (`codeteam/F00x`) plus a thread-bound backlog item/task;
  never call `update_workflow` with a bare F-ID; verify `get_workflow_sop` on the thread after write.
- **Scope**: Mission Hub integration.

## LL-005: Mission Hub wiring is a kickoff step, not a closeout step

- **Observed**: F002 ran to completion with no thread feature link, no task, and no WorkflowSop;
  retrospective wiring hit the ID collision above.
- **Root cause**: the repo SOP was followed, but the Clowder Mission Hub checklist was skipped.
- **Guardrail**: kickoff = `set_thread_metadata` + `create_task` (project-scoped feature ID) +
  `update_workflow` with stage/baton/resumeCapsule. Closeout updates the same record.
- **Scope**: feature lifecycle.

## LL-006: Credential test files need explicit modes and cleanup in `finally`

- **Observed**: The live E2E wrote the real key to a 0644 temp `auth.json` while the report claimed
  0600; setup outside `try` could also leave the fetch wrapper installed.
- **Root cause**: `writeFileSync` defaults to umask-based modes; setup happened before `try`.
- **Guardrail**: credential files use explicit `{ mode: 0o600 }` with a `statSync` assertion; all
  setup goes inside `try`, and `finally` restores globals, disposes the session, and removes the
  temp root; abort before the test timeout and contain the abort rejection.
- **Scope**: test security.

## LL-007: A fresh worktree needs the pinned model catalog before `check`

- **Observed**: `npm run check` failed in a new worktree with `getModel(...)` typed as `never`,
  which looked like a code error.
- **Root cause**: generated model data was absent; `getModel` degraded without the hydrated catalog.
- **Guardrail**: hydrate the pinned catalog before build/check in any fresh worktree; treat
  `never`-typed model lookups as an environment signal first, not a code regression.
- **Scope**: local verification.

## LL-008: `gh pr checks --watch` has an empty window right after push

- **Observed**: The watcher exited 1 with "no checks reported" immediately after a push; GraphQL also
  returned transient EOFs.
- **Root cause**: check-runs are attached asynchronously after the workflow run is created.
- **Guardrail**: poll the REST `check-runs` endpoint until a non-empty set exists, then watch; retry
  on EOF rather than treating it as a failure.
- **Scope**: CI tooling.
