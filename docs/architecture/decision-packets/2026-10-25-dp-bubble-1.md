# DP-BUBBLE-1: bubble-pipeline 签字范围

> **Operator 决定（2026-10-25）**：`DP-BUBBLE-1=A`。W1 立即冻结；W7 记为 `approved-for-direction`，W4 dogfood 后按实测确认/修订。本 packet 已冻结。

## 0. 一句话

只冻结卡住首个代码闭环的 W1 message identity schema；W7 只读 timeline/UX 契约保留方向性批准，等 W4 dogfood 的真实体验校准，不提前把未验证的文案/恢复入口写成硬契约。

## 1. 先看结论

| 决策 | 选项 | 推荐 | 影响面 | 不拍的后果 |
|---|---|---|---|---|
| DP-BUBBLE-1 签字范围 | A=W1 立即冻结 + W7 approved-for-direction；B=W1+W7 全冻结；C=全部等 W4 dogfood | **A** | W1 开工时间、W7 返工风险、Wave B 节奏 | W1 schema 继续草案，首个代码闭环被契约门挡住 |

## 2. 背景

- bubble-pipeline 三猫 review 已完成：烁烁 accept、砚砚 accept-with-modify、墨墨 accept-with-modify；无 P1，3×P2 + 12×P3 已回写。
- W1 是加法 schema：`messages.seq`、`runs.response_message_id`、`runs.execution_kind`、`dispatch_refs_json`；它是 message identity / dispatch projection 的硬前置，直接卡住 W1 首个代码闭环。
- W7 是只读投影/体验契约：`ThreadTimelineDTO`、reconnect 全量 snapshot、unknown `missingEvidence`、provisional cache。其文案与恢复入口最适合用 W4 dogfood 的真实体验校准。
- 原计划 Wave B 整体排在 W4 dogfood 后；本项是 operator 指定提前 review 的例外，不应因此把整个 Wave B 提前。

## 3. 选项

| 选项 | 行为 | 价值 | 代价 |
|---|---|---|---|
| **A（推荐）** | W1 立即 approved 并冻结；W7 标 `approved-for-direction`，W4 dogfood 后按实测确认/修订 | W1 马上可开工；W7 不阻塞 W4；不提前锁死未验证 UX | W7 可能有一轮小修订 |
| B | W1 + W7 全 approved、全冻结 | 一次签清；W7 按现契约实现，后续变更走修订 | dogfood 后 W7 文案/恢复入口可能返工，修订成本更高 |
| C | 全部暂缓到 W4 dogfood 后 | 最大程度保留学习空间 | W1 message identity 继续草案，W1 无法开工 |

## 4. 推荐理由

W1 是低风险、可回滚的加法 schema，且是首个代码闭环的硬前置；W7 是只读面，错误成本主要是返工而不是数据/权限风险。把两者拆开签，既不让 W1 等 UX 学习，也不把未验证的 UX 细节提前钉死。这与 0004 中“Wave B 等 W4 dogfood”的原节奏一致，只是把 W1 的硬前置提前解冻。

## 5. 已定边界（不需要再拍）

- 唯一 message store = `messages`；不建第二 message store / 前端 canonical reducer ledger。
- `dispatchRefs` 只在真实 delivery 出现；Queue pending 不是 delivery；`inputRead` 不是 handled。
- terminal 只来自 `runs.status` + response lifecycle；one terminal per run。
- `unknown` 必须是带 `missingEvidence` 的诚实状态，不是裸徽章。
- 不恢复 F254 closure/supplement 运行时；F322 InteractiveBlock 不造第二 bubble identity。
- `codeteam/` 仍 untracked；本次只改文档，不 commit/push。
